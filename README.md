# NIMF (Not In My Frame)

> 스트리밍 중 노출되면 안 되는 인물·물건·단어를 AI로 감지하고 대응하는 실시간 콘텐츠 보호 솔루션

## 프로젝트 개요

NIMF는 스트리머가 방송 중 놓치기 쉬운 위험 요소를 실시간으로 감지하고, 알림·블러·음소거 등의 대응을 제공하는 팀 프로젝트입니다.

- 기간: 2025.07.07 - 2025.08.18
- 인원: 6명
- 담당: 프론트엔드, UI/UX
- 주요 기술: React, TypeScript, Zustand, Figma, WebRTC, WebSocket

## 해결하려던 문제

실시간 방송에서는 타인의 얼굴, 금지 물품, 욕설과 같은 위험 요소가 순간적으로 노출될 수 있습니다. 스트리머가 방송과 모니터링을 동시에 수행하기 어렵다는 점에 주목해, AI 탐지 결과를 즉시 이해하고 대응할 수 있는 보조 인터페이스를 설계했습니다.

## 주요 기능

### 영상 모니터링

- 스트리머 외 인물 감지
- 위험·금지 물품 탐지
- 탐지 영역 블러 처리

### 음성 모니터링

- 욕설·비속어 인식
- 탐지 구간 음소거 처리

### 알림과 대응

- 방송 화면에 노출되지 않는 스트리머용 경고 UI
- 소리 알림
- 상황에 따른 행동 안내 메시지

## 김대정의 역할과 기여

- Figma를 활용한 서비스 화면과 사용자 흐름 설계
- React와 TypeScript 기반 프론트엔드 구현
- Zustand를 활용한 화면 및 탐지 상태 관리
- 팀 요구사항을 화면 구조와 상호작용으로 구체화
- 백엔드와 프론트엔드 사이의 요청·응답 데이터 흐름 정리

## 핵심 설계 포인트

### 탐지 결과의 우선순위 표현

실시간 환경에서는 모든 정보를 같은 강도로 표시하면 방송 진행을 방해할 수 있습니다. 탐지 대상과 위험 수준을 빠르게 구분할 수 있도록 경고의 위치, 강도, 메시지 흐름을 설계했습니다.

### 비동기 상태 관리

영상·음성 탐지 결과가 지속적으로 갱신되는 환경을 고려해 화면 상태와 서버 데이터를 분리하고, 탐지 상태가 UI에 일관되게 반영되도록 구성했습니다.

### 기술보다 사용자 대응 흐름

탐지 정확도만으로는 문제를 해결할 수 없었습니다. 사용자가 경고를 확인한 뒤 어떤 행동을 해야 하는지까지 연결하기 위해 알림, 시각 처리, 행동 안내를 하나의 흐름으로 다뤘습니다.

## 회고

첫 프론트엔드 팀 프로젝트를 통해 화면 구현뿐 아니라 팀 간 데이터 계약과 상태 관리가 중요하다는 점을 배웠습니다. 특히 실시간 서비스에서는 기능의 존재보다 사용자가 상황을 즉시 이해하고 대응할 수 있는 인터페이스가 중요하다는 경험을 얻었습니다.

## 향후 개선

- 탐지 정확도와 응답 지연을 확인할 수 있는 평가 지표 추가
- 실제 스트리밍 환경을 반영한 성능 테스트
- 경고 단계와 사용자 설정 기능 고도화
- 실행 및 배포 절차 문서화
